01CONFIG

「作る」と「読み込む」はどう違うのか

procedural generation — 手続き的生成

この章の3行まとめ
  • ふつうの3Dは、誰かが作ったモデルファイルを読み込んで表示します。
  • このプロジェクトは逆で、実行した瞬間に座標も模様も計算で作ります。これを手続き的生成といいます。
  • だから1個ずつ形が違い、焼き加減をあとから変えられ、しかもデータが軽い。

ゲームや映画に出てくるお菓子の3Dは、ふつう誰かが専用ソフトで作ったモデルファイルを読み込んで表示します。 ファイルの中には「頂点1番は(3.2, 1.1, 0.4)」といった座標が何万個も保存されていて、 表面の模様も写真として一緒に入っています。プログラムはそれを並べて画面に出すだけです。

このプロジェクトは逆のことをしています。ファイルも写真も読まず、 プログラムを実行した瞬間に座標を計算で作り、模様も1ピクセルずつ計算で描く。 これを手続き的生成（プロシージャル生成）と呼びます。 お菓子と相性がよく、いいことが3つあります。

  • 1個も同じにならない — 数値を少し揺らすだけで、形の違う個体がいくらでも出てきます。 皿のクッキー8枚が全部同じ形だと、その瞬間に嘘に見えます。
  • あとから変えられる — 「もう少し焼く」がスライダー1本で通ります。 写真を貼る方式なら、焼き加減の数だけ写真を用意することになります。
  • 軽い — 15本ぜんぶ合わせて 1.3MB ほどのテキストだけです。 モデルファイルも、模様の写真も、1枚もありません。

その代わり、形や色を言葉ではなく数式で説明できないと作れません。 「焼きドーナツってどんな形?」に 「1個の中に肌が2種類ある。型に接した面は滑らかで色が濃く、わずかに照る。 空気に膨れた面はざらついて色が浅く、割れている」と 答えられるかどうかが勝負になります（ドーナツ.js の冒頭のコメント）。 だからこのプロジェクトのコードは、コメントの半分がお菓子の観察記録です。

ほとんどのファイルが、同じ層でできている

クッキーもチョコレートもドーナツも、ファイルの構造はほとんど同じです。上から順に読めば、 どのお菓子でも同じ場所に同じ役割のコードがあります。

層の順番には理由があります。下の層は上の層を知らなくても動くように積んであるからです。 乱数（1）はノイズ（2）を知らないし、ノイズは形（4）を知らない。 だから途中の1層だけ差し替えれば、別のお菓子になります。 クッキー.js の7種類は、まさにそれです。4. Section に渡す外形と断面の数値を変えるだけで、 サブレがクラッカーになり、型押しビスケットになる（→ 06章）。

章は、お菓子の作り方の順に並んでいる

このサイトの章立ては、ファイルの層ではなくお菓子を作るときに必要になる技術で分けてあります。 第I部で全部のファイルに共通する道具をそろえたら、あとは実際のお菓子作りと同じ順番です。 生地を形にして、焼いたり掛けたりして、皿に盛って、最後に硬い面では作れないものへ。

野菜のときと変わったところ

この教材には姉妹編（やさいのつくりかた）があり、そちらでは 4. Profile（横顔の折れ線）が形の中心にありました。 お菓子では、そこが 4. Fields や 4. Section という名前に変わっているファイルが多い。 野菜は「軸のまわりに回せば作れる」ものが多いのに対し、 お菓子は型で抜いてあったり、潰してあったり、垂れていたり、巻いてあったりして、 回転体ではないものが増えるためです。

「焼く」と「固める」が、そのままコードにある

野菜とお菓子のいちばん大きな違いはここです。お菓子の多くには火が通っている。 その結果として、表面の色が場所ごとに違い、水分が飛び、艶が出て、形が変わる。 クッキー・パンケーキ・たい焼きには bake（焼き加減）という名前の変数があり、 たい焼きは焦げぎわを char / burn として、焼き団子は焦げ目を scorch として持っています。 焼き色は最後に上から塗る飾りではなく、形と一緒に決まるものです。 それを扱うのが10章です。

一方で、チョコレートとチョコバナナには火が通っていません。溶かして、型に流すか浸して、固めたものです。 そこでは焼き色の代わりに、ブルーム（表面の白い粉）や、垂れて止まった滴が手がかりになります。

読む順番のおすすめ。 最初の1本は花見団子.jsがいちばん素直です（球を少し潰して串に刺すだけ）。 次に月見団子.js、慣れたらクッキー.js。 チョコレート.jsとパンケーキ.jsは分量が多いので後回しでかまいません。 章の例は、すべてこの15本から取っています。
やってみよう
  1. クッキー.js の先頭のコメント（構成 0〜9）を読んで、他のファイルにも同じ並びがあるか確かめる。
  2. 手続き的生成のいいところ3つを、自分の言葉で1行ずつ書いてみる。
  3. 15本のファイルを検索して、bake / char / burn / scorch という語がどのファイルに出てくるか調べ、「焼いたお菓子」と一致するか確かめる。
  4. 身のまわりのお菓子で「数式で説明できそうな形」を3つ探し、上の表のどの章の作り方になるか当てはめる（例：バウムクーヘン、マカロン、板チョコ）。
