# おかしのつくりかた（VirtualSweetsFactory）

コードでお菓子をつくる技術ノート — [Babylon.js](https://www.babylonjs.com/) による手続き的モデリングの学習サイト。

**→ [https://cx20.github.io/VirtualSweetsFactory/](https://cx20.github.io/VirtualSweetsFactory/)**

3Dモデルファイルも写真も **1枚も読み込みません**。点の座標を計算で並べ、焼き色をその場で1ピクセルずつ描き、
たれの濃さを「厚み × 吸収係数」から解く。そうやって作ったお菓子 15 本のサンプルと、
それを中学生・高校生向けにほどいた全 18 章の解説で構成しています。

必要な数学は sin・cos、座標、比例、指数関数（`exp`）、それに少しのベクトル（内積・外積）。
高校1年までの内容でだいたい追えます。

甘いものは別腹です。このリポジトリは、料理 30 本を扱った
**[たべもののつくりかた（VirtualFoodCourt）](https://github.com/cx20/VirtualFoodCourt)** から、
お菓子だけを切り出したものです。野菜と果物を扱った
**[やさいのつくりかた（VirtualVegetablePlant）](https://github.com/cx20/VirtualVegetablePlant)** もあります。
第I部（01〜11章）は 3 つともほぼ共通の内容なので、どこから読んでもかまいません。
第I部の例に出てくるトーストやたこ焼きなどの .js は、サイト上ではたべもの編のソースへのリンクになっています。

## まず動かす

サンプルは [Babylon.js Playground](https://playground.babylonjs.com/) 用の形になっています。
インストールは何も要りません。

1. [playground.babylonjs.com](https://playground.babylonjs.com/) を開く
2. 左側のコードを全部消す（`Ctrl`+`A` → `Delete`）
3. [samples/花見団子.js](samples/花見団子.js) の中身を全部コピーして貼る
4. **Run**（`Alt`+`Enter`）

数秒〜十数秒待つと、皿の上に団子の串が出てきます。詳しくは `start.html`（00 まず動かしてみる）を参照してください。

サイト内の `zukan.html`（図鑑）からは、Playground へ行かずにその場でサンプルを実行することもできます。

## ローカルで開く

`file://` でも一応動きますが、ソースビューアとサンプル実行は `assets/src/` の複製（ビルド生成物）に頼る形になります。
HTTP で開くのが確実です。

```sh
cd VirtualSweetsFactory
node tools/build.js          # HTML 全ページと assets/src/ を生成
npx serve .                  # 任意の静的サーバでよい
```

### 色について

`assets/site.css` の顔料（`--p-kitsune` など）は、すべて**サンプルのコードに実際に書かれている値**を
sRGB 0-1 → 16進に直したものです。第I部をたべもの編と共有しているので、たべもの編のサンプルから拾った色も残っています。
出典はコメントに残してあります。

新しい色を足すときも、どこかの `samples/*.js` から拾ってください。

| --- | --- |

| [ゼリー.js](samples/ゼリー.js) | 色は塗らずに光路長から解く（`tintColor ^ 厚み`）。菊型の溝は母線の法線方向に彫る |
| [アイス.js](samples/アイス.js) | 距離関数 → 格子 → 1回ぼかし → サーフェスネット。ディッシャーの筋・めくれ・気泡を焼き込み、下から溶かす |

多くのファイルの先頭に「構成」というコメントがあり、`0. CONFIG` → `1. Rng` → `2. Noise` →
`3. Mesh utils` → `4. Fields / Section / Shape` → `5. TextureLab` → `6. 本体` →
`7. 皿・板・トレイ` → `8. Scene / 物理` → `9. GUI` の順に並んでいます。

コメント中の **【対策】** は「一度失敗して直した記録」です。なぜその数値なのか、
なぜその順番なのかは、たいていそこに書いてあります。

## 章立て

### 第I部 — 1皿をつくる（00〜11）

1本の .js ファイルを、上から順にほどいていく構成です。たべもの編と共通の内容です。

| | 章 | 内容 |
| --- | --- | --- |
| 00 | まず動かしてみる | インストールなし。ブラウザだけで15本を動かす手順 |
| 01 | 手続き生成 | モデルも写真も読み込まず、実行した瞬間に座標と模様を計算で作る |
| 02 | 乱数 | `Math.random()` を使わない理由。種を渡すと毎回同じ結果になる乱数を書く |
| 03 | ノイズ | となり合う値がなめらかにつながる乱数。重ねると焼きムラや生地の肌理になる |
| 04 | かたち | 断面を1枚描いて軸のまわりに回す。回らないものは外形×縦断面で作る |
| 05 | 面と法線 | 3Dモデルの正体は座標の配列と三角形の番号表。裏返ると立体が消える理由 |
| 06 | テクスチャ | UVで立体と画像を対応させ、模様を1ピクセルずつ計算で描く（色・粗さ・凹凸の3枚） |
| 07 | PBR | 「照っている」「ぬれている」を数値で書く。粗さ・クリアコート・透け |
| 08 | 物理 | 皿への盛り付けは手で置かない。重力と摩擦を与えて Havok に任せる |
| 09 | 部品 | 細かいトッピングは、テクスチャに描くと消える。実体のかけらとして撒く |
| 10 | 曲がり | 先に軸を決め、断面を軸に垂直に置いていく（掃引） |
| 11 | 光 | 同じものでも光で別物になる。IBL・影・露出・トーンマッピング |

### 第II部 — たれが掛かって、やわらかいものをつくる（12〜13）

硬い球と色の塗り分けでは作れない、お菓子の 2 つの難所。どちらも、もとはたべもの編の第II部にあった章です。

| | 章 | 内容 |
| --- | --- | --- |
| 12 | たれ | たれを茶色く塗ると光沢のない卵になる。色は厚みから解くもの（`exp(-係数×厚み)`） |
| 13 | 潰れ | 団子は真球では積めない。潰した体積の行き先と、接触の縁の土手 |

焼き色・透け・作り分けの章は、たべもの編の 12・13・15 章にあります。

### 第III部 — 揺れて、透けて、ひとつの塊になる（14〜17）

あとから加わった 5 本（プリン・ゼリー・アイス・飴細工・綿菓子）で初めて出てくる技術。たべもの編には無い、このサイトだけの章です。

| | 章 | 内容 |
| --- | --- | --- |
| 14 | 揺れ | Havok にソフトボディは無い。減衰するばね（モード）の重ね合わせで揺らし、法線も一緒に動かす |
| 15 | 透け | ゼリーの色は光が中を通った距離で決まる（`exp(-σ×光路長)`）。厚みは近似せずに測る |
| 16 | 塊 | 部品を距離関数で書いて smin で溶かし、格子からサーフェスネットで面を張る |
| 17 | 糸 | 表面の無い綿菓子。帯に沿った 3 万 2 千本の糸を線で描き、芯の深度を先に書いて裏を隠す |

各章には **その場で動かせる実験** が 1 つずつ入っています（全 17 個）。
外部ライブラリは使わず、Canvas 2D の上にミニチュアのレンダラを組んであります。

## サムネイルの収録

```sh
node tools/shoot.js            # samples/ のぜんぶ
node tools/shoot.js クッキー   # 名前で絞り込み（部分一致）
```

ヘッドレスの Chrome を DevTools プロトコルで動かし、**サンプルを実際に実行して撮ります**。
生成物は `assets/thumbs/` に入り、リポジトリに入れて配ります。

1. ローカルに HTTP サーバを立てる（`file://` だと WebGL も CDN も面倒）
2. Chrome を `--headless=new --use-angle=swiftshader` で起動（GPU が無くても描ける）
3. `createScene()` の完了を待ち、**メッシュが増えず・動かなくなる**まで待つ
   （固定時間で待つと、クッキーが宙に浮いた絵で撮れる）
4. 待つあいだは 1/6 解像度・影と後処理オフで回し、撮る直前に等倍へ戻す
5. GUI（右下のスライダー）だけ隠し、描かれた画素から被写体の枠を求めて切り出す

環境変数: `SHOOT_DEBUG=1`（各段階の所要時間と切り出し枠）、`SHOOT_DUMP=1`（メッシュ一覧）、
`SHOOT_BUILD_TIMEOUT`（組み立て待ちの上限 ms、既定 600000）。

再収録が要るのは**サンプルの見た目を変えたときだけ**です。

## 動作確認

```sh
node tools/verify-play.js      # play.html で全サンプルが本当に動くか
```

重い後処理を使うサンプルは SwiftShader だと1枚に数秒かかり、
既定の3秒では描画ループが進まないことがあります。そのときは見張る時間を延ばしてください。

```sh
VERIFY_FRAME_WAIT=30000 node tools/verify-play.js チョコレート
```

`play.html` を実際に開いて、`createScene()` が値を返し、描画ループが回り、
ページ内にエラーが出ていないことを確かめます。
