17Jiggle

プルプルは、6本のばねの重ね合わせ

modal deformation — 物理エンジンに無い、やわらかさの作り方

この章の3行まとめ
  • Havok にはソフトボディ（やわらかい物体）が無いので、落ちる・着地するは Havok に、揺れは自前の計算に分けます。
  • 揺れは減衰するばね（振動子）を数本だけ回し、決まった形の変形を足し合わせて作ります。
  • 目に付くのは形の変化よりハイライトが走ること。だから法線も一緒に動かします。

皿の上に落としたプリンは、ぷるんと2〜3回揺れて止まります。 15章では盛り付けを物理エンジン（Havok）に任せましたが、Havok が扱えるのは硬い物体だけです。 プリン.js の冒頭にこうあります。

「Babylon の Havok プラグインが公開しているのは剛体・シェイプ・拘束までで、 ソフトボディは出ていない。そこで役割を分ける。 Havok … 落下・着地・皿との接触。自前 … 揺れそのもの」

落ちてくる・皿に当たる・止まる、までは硬い物体として Havok が計算します。 Havok から「いま速度がどれだけ急に変わったか」（＝着地の衝撃）を受け取り、 それを入力にして揺れだけを自分で計算します。 揺れの計算に使うのは、ばねにおもりを付けて揺らしたときと同じ式です。

実験 — 揺れ方は、周波数と減衰比の2つで決まる

—

「ゆらす」かキャンバスのクリックで揺れます。右の線は揺れの大きさ q の記録です。 減衰比を 0.3 にすると寒天、0.03 にするとゴムになります。 「法線も一緒に動かす」を切ると、形は揺れているのにハイライトが止まったままになります。

揺れの「形」は、先に決めておける

やわらかい物を本気で計算すると、1万個の頂点が互いに押し合う連立方程式になります。 それを毎フレーム解くのは重すぎます。そこで、揺れ方を決まった数パターン（モード）に限ります。 プリン.js が使っているのは6つです。

#揺れ方形周波数減衰比
0, 1横に首を振る（せん断 X / Z）底を固定した片持ちのたわみ 1.5s² − 0.5s³5.8 Hz0.105
2縦につぶれる・のびる上が沈むぶん胴が太る（体積を保つ）9.2 Hz0.145
3, 4上から見て楕円にゆがむcos 2θ / sin 2θ12.5 Hz0.175
5天面が太鼓のように上下天面の中心ほど大きい15.5 Hz0.240

s は底からの高さを 0〜1 にしたもの、θ は上から見た角度です。 どのモードも「静止しているときの形」だけで決まる関数なので、頂点ごとの動き方 Φk を 組み立てるときに1回だけ計算して焼いておけます（焼き込み）。 実行中にやることは、6本のばねの値 qk を掛けて足すだけです。

減衰比が、素材を決める

周波数は「どれだけ速く揺れるか」、減衰比 ζ は「どれだけ早く収まるか」です。 プリン.js は周波数を実物から見積もっています。カスタードのかたさ（数 kPa）と密度から、 揺れが伝わる速さはおよそ 1 m/s。高さ 4.3cm の片持ちなら f ≈ c / (4H) ≈ 5.8 Hz。 「2〜3回揺れて1秒以内に収まる」のは、減衰比 0.10〜0.15 にあたります。

  • プリン — ζ = 0.105。2〜3回で止まる
  • ゼリー — ζ = 0.055、周波数は 8.0 Hz と高め。カスタードよりよく響き、3〜4回揺れる（ゼリー.js）
  • 寒天 — ζ を 0.3 まで上げると、ほとんど揺れずに止まる
  • ゴム — ζ を 0.03 まで下げると、いつまでも揺れ続ける

見た目の形は同じでも、この2つの数だけで「何でできているか」が伝わります。 どちらのサンプルにも、GUI でまとめて振れる freqScale（やわらかさ）があり、 プリンは 0.50、ゼリーは 0.70 を掛けて、写真より少しゆっくり大きく揺らしています。

動いて見えるのは、ハイライト

頂点の位置だけを動かして法線を放っておくと、揺れているのに濡れて見えません。 プリン.js のコメントによれば、プルプル感の主成分は形の変化ではなく 「ハイライトが表面を走ること」です。04章で見たとおり、明るさを決めるのは法線です。

変位 u が小さいとき、変形後の法線は n' ≈ normalize(n − (∇u)ᵀ n) で近似できます。 静止時の法線 n は決まっているので、この (∇Φk)ᵀ n も頂点ごとに焼いておける。 結果として、頂点1つあたり「モード数 × 6個の数」を持っておけば、位置も法線も足し算だけで動きます。

つまずきポイント

表示のフレームごとに積分すると、速いモードが暴れます。 60fps の 1/60 秒で 15.5Hz のモードを進めると、1歩で ω×h が 1.6 になって符号が振動し、発散します。 プリン.js は内部で 1/240 秒に刻んで回しています。

衝撃は「力」ではなく「速度の差」で渡す。 着地の加速度を力として積分していたら、60fps と 144fps で揺れの大きさが2倍違いました。 Havok から受け取った速度の差 Δv をそのまま q の速さに足せば、刻み幅が効かなくなります。

大きく揺らすと裏返る。 モードの形は小さな変形を前提にした近似なので、縦モードを高さ H まで押すと潰れきって裏返ります。 ばねは線形のまま回し、表示に渡すところで tanh を通して頭打ちにします。 実物のゲルも大きく歪むと硬くなるので、挙動としても外れていません。

やってみよう
  1. プリン・ゼリー・寒天・ゴムを順に押し、「ゆらす」で止まるまでの回数を数える。
  2. 「法線も一緒に動かす」を切って揺らし、何が足りなく見えるかを1行で書く。
  3. プリン.js で modeZeta を全部 0.03 にして Run し、皿の上で何に見えるか確かめる。
  4. ゼリー.js の modeFreq / modeZeta をプリン.js と並べ、どのモードがどれだけ違うか表にする。
