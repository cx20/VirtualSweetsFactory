16Topping

スプレーは、上から振ったところにだけ付く

instancing / scattering — 実体としてのトッピング

この章の3行まとめ
  • カラースプレー・チョコチップ・ココナッツ。絵に描くと消えます。1粒ずつ実体として置く必要があります。
  • 同じ粒を何百個も置くときはインスタンスを使い、1粒ぶんの形を使い回します。
  • どこに付くかは振った向きで決まり、付いた粒は半分沈む。均等に並べると、振ったようには見えません。

チョコバナナにカラースプレーを振ります。テクスチャに色の点を描けばよさそうですが、 これは失敗します。1mm の粒は、少し離れるとミップマップ（縮小版の画像）で溶けて 色のにじんだ靄になります。ドーナツ.js のコメントはもっと手厳しくて、 「テクスチャの斑点で済ませると、真上から見た1個は誤魔化せても、皿に転がった瞬間に『印刷』だとわかる」。 粒を「振りかけた」ように見せられるのは、実体の粒だけです。

そこで、チョコバナナ.js はスプレーを小さなカプセル（両端の丸い棒）として1本ずつ置きます。 クッキーのチョコチップは潰れた球、ドーナツのココナッツは薄い板、レモンの皮は細い小片。 どれも実体です。

インスタンス — 形は1粒ぶんだけ作る

500本のスプレーを1本ずつメッシュにすると、頂点の配列も描く命令も500個ぶん要ります。 そこで、形は1本だけ作り、位置・向き・大きさ・色だけを500本ぶん持つ。 これがインスタンスです。GPU 側は「同じ形を、行列を差し替えながら500回描く」だけになります。

ドーナツ.js は別のやり方で、粒を全部1つのメッシュにまとめています。 「1粒ずつメッシュにするとドローコールが 90 個増える」ので、低い解像度の球を粒の数だけ 1つの頂点配列に書き込む。粒の形を1個ずつ歪ませたいときは、こちらが向いています。

どこに付くかは、振った向きで決まる

ここがトッピングでいちばん大事なところです。チョコバナナ.js の冒頭： 「カラースプレーは全周には付かない。横にして上から振るので、上を向いていた背（凸側）と 片側の肩にだけ密に付き、腹（凹側）はチョコの地のまま」。 全周に一様に撒くと、「スプレーをまぶした」ではなく「柄の布」になります。

最後の2行も大切です。「スプレーは乾く前のチョコに半分沈む。表面に置いただけにすると、 乗っているだけの粒に見える」。ドーナツ.js にも同じ記録があり、 「粒を面の上にきれいに載せると、乾いてから振りかけたように見える。実際は固まる前のグレーズに沈むので、 半分近く埋まっている」。クッキーのチョコチップも、生地に半分ほど沈めてあります。

実験 — スプレーを撒いて、重なりをほぐす

—

チョコがけドーナツを真上から見たところです。色の重みはチョコバナナ.js の「カラフル」から。 「格子に並べる」は、重なりがゼロなのに一目で嘘と分かります。 乱数で撒いてから少しだけほぐす、が実物に近い落としどころです。

重なりをほぐす — ただし、やりすぎない

乱数で撒くと、必ず何本かが同じ場所に重なります。重なった粒は、 光の当たり方が同じになるので1つの濃い染みに見えます。 そこで、近すぎる組を見つけて、離れる方向に少しずつ動かす操作を何回かくり返します。

ここで大事なのはやりすぎないことです。ほぐしきると格子になり、 「振りかけた」ではなく「並べた」に戻ってしまいます。 上の実験でほぐす回数を 30 まで上げると、それが見えます。 たい焼きの断面のつぶあんも同じで、たい焼き.js には 「粒を等間隔に並べると水玉の布になる。大小と向きを散らし、一部は重ねて『詰まった餡』に見せる」とあります。

粒を、模様ではなく実体で作る判断

どこまでを実体で作り、どこからをテクスチャで済ませるか。 サンプルは、だいたい次の基準で分けています。

大きさやり方例
数 mm 以上実体のメッシュ。シルエットに出るチョコチップ・カラースプレー・つぶあんの粒
1〜3mm の薄いもの板に近い薄い実体。輪郭は要るが厚みはほとんど要らないドーナツのココナッツ・レモンの皮
1mm 未満法線マップとアルベド。凹凸だけ嘘をつくクッキーの砂糖の細粒・気泡の穴・型押しの筋
つまずきポイント

薄い板は、裏から見ると消えます。 片面しか描かない設定のままだと、撒いたかけらの半分が見えなくなります。 両面描画（backFaceCulling = false）にするか、 裏返っているものを作るときに向きを揃えます。

影を落とす対象に入れると、一気に重くなります。 500本の粒全部に影を計算させる必要はありません。 大きいものだけ影を持たせ、小さい粒は外します。

同じ名前で何個も作ると、あとで自分が困ります。 Babylon.js は new BABYLON.Mesh(name) のときに id にも同じ値を入れるので、同じ名前で何本も作ると id まで同じになります。 画面は正しく出るので気づきません。ところが Playground の Inspector で3本目をクリックすると、別の1本が選ばれます。Inspector が id で引き当てるときに取り違えるためです。

厄介なのは、名前だけ直しても直らないことです。 あとから mesh.name を変えても id は元のまま残ります。 チョコバナナ.js とロールケーキ.js は、メッシュを作るたびに named() という関数を通して、 「mesh.name と mesh.id を必ず一意にする（Inspector の選択が先頭に吸われるのを防ぐ）」ようにしています。 同じ部品を何百個も並べる章なので、いちばん踏みやすい落とし穴です。

やってみよう
  1. 本数を 260 にして、ほぐす回数 0 と 10 を見比べる。
  2. 「格子に並べる」に切り替え、なぜ嘘に見えるのか1行で書く。
  3. チョコバナナ.js で facing を検索し、どの向きから振ったことになっているか読む。
  4. ドーナツ.js の TOPPINGS で embed（沈み具合）の値を探し、トッピングごとに比べる。
